# Spike 0001: steadier kernel benchmarks (b18) on Edge (NVIDIA)

Date: 2026-11-26 (UTC). Machine: the owner's Linux laptop. Code: branch `spike-0001/steady-bench`, on top of
`spike-0001/dispatch-gaps` (#75). All values below are quoted from the reports in this directory.

## Why

`2026-11-b18-dispatch.md` found the GPU going idle between the benchmark pages' passes, because each page waited for one
pass before submitting the next, and its SM clock changed during a run. The GEMM, transform and dispatch benchmarks now
time their kernels through `test/gpu/timing.js`:
- **Warm-up:** the same work for at least 300 ms, then the timed passes, all submitted at once with no waiting between
  them. The page waits once, at the end.
- **Timestamps:** each timed pass has its own pair.
- **The figure:** the span from the first timed pass's start to the last one's end, divided by the number of timed
  passes (7), then by the dispatches per pass (30 for GEMM and transforms).

GEMM run 1 used the median of the per-pass intervals instead of the span. Runs 2 and 3 record both
(`passMedianMsPerDispatch`); across their rows the two differ by 0–15.03% of the span figure.

The network pass in the dispatch benchmark still awaits each `net.profile` call; that wasn't changed.
