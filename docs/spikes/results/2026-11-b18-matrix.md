# Spike 0001: matrix hardware (subgroup matrices) for b18 on Edge (NVIDIA)

Date: 2026-11-26 (UTC). Machine: the owner's Linux laptop (RTX 3080 Laptop GPU, NVIDIA driver 620.73). Code: branch
`spike-0001/subgroup-matrix`, on top of `spike-0001/subgroup-gemm` (#79). All values below are quoted from the reports
in this directory.

## The switch

Matrix hardware is reachable from WebGPU only through Chromium's experimental `chromium-experimental-subgroup-matrix`
feature, which Dawn marks unsafe. The owner allowed one exception to the no-flags rule for this test: the separate test
Edge, and nothing else, was launched with `--enable-unsafe-webgpu` added to the launch used in #48:
`msedge --user-data-dir=<temp dir> --remote-debugging-port=9223 --no-first-run --no-default-browser-check --ignore-gpu-blocklist --use-webgpu-power-preference=force-high-performance --enable-unsafe-webgpu`.

- **Driver:** `vulkaninfo` (read-only) shows the NVIDIA driver with `VK_KHR_cooperative_matrix`, `cooperativeMatrix`,
  `vulkanMemoryModel`, `vulkanMemoryModelDeviceScope`, `subgroupSizeControl` and `computeFullSubgroups`. These are
  the conditions in Dawn's `PhysicalDeviceVk.cpp`.
- **Edge:** 158 with the switch offers `chromium-experimental-subgroup-matrix`; without it, it doesn't. See
  `adapterFeatures` in [`…-adapter-edge-nvidia.json`](2026-11-b18-matrix-adapter-edge-nvidia.json) and in the earlier
  reports.
- **Shader warnings:** the browser log shows "use of deprecated builtin" warnings for `subgroupMatrixLoad` and
  `subgroupMatrixStore` as used here.
- **Users:** none of this reaches users until browsers ship the feature without a switch.

## What was built

- **`GEMM_MMA`** (kernels.ts): GEMM v2's bindings, parameters and dispatch on 16 × 16 × 16 f16 → f32 subgroup matrices.
  - A workgroup is one 32-lane subgroup computing fm × fn accumulators.
  - `direct`: when the workgroup's tile and K are inside the matrices, it loads the matrices straight from A and B.
    Otherwise it copies 32-wide chunks of k into workgroup memory first.
  - `ta`: A stored transposed, [M][K].
  - The result goes through workgroup memory so threads can add the bias and residual.
  - It sums in another order than v2 and v3, so its results differ from theirs by rounding.
- **`GpuNetwork` option `winoGemm: 'mma'`:** runs the Winograd GEMMs on it (2 × 1, direct, with the Winograd weights
  stored transposed). The 1×1 convolutions keep `gemm`.
  - It needs `precision: 'f16'` and the feature with an f16 → f32 16 × 16 × 16 shape.
  - It is off by default.
- **The device** requests `chromium-experimental-subgroup-matrix` when offered, and records `subgroupMatrixConfigs`.
- **The GEMM benchmark** adds the matrix kernels and a raw-throughput test (`matrixPeak`):
  - `matrixPeak` is 3072 workgroups × 1024 iterations × 4 independent multiply-accumulates on values already in
    registers.
  - Matrix kernels are held to the reference check's tolerance against v2, instead of exact equality.
- **The check page** adds two `winoGemm: 'mma'` variants when the device offers the feature.

## Raw throughput

`matrixPeak`: 33.03 TFLOPS in the final GEMM report. The other reports with it: 41.47 TFLOPS (explore 7).
The best GEMM here reaches 11.37 TFLOPS.

**Tried on the way, kept as reports** (`…-gemm-explore-{1,2,3,4,7}-edge-nvidia.json`):
1. **Copying every chunk into workgroup memory, one f16 per thread at a time** (no `direct`): 64.4 ms per network at
   batch 16 against v3's 16.1.
2. **Direct loads, 1×1 to 4×4 accumulators:** more accumulators were slower at batch 16. 2 × 2 was best at 32 and 64.
3. **Transposed A, and 2 × 1 / 1 × 2:** transposed A was faster on the Winograd shape.
4. **2–12 steps of k unrolled, loads issued first (`uk`):** no consistent change. The option is kept, default 2.
5. **A tiled kernel** (2–4 subgroups per workgroup sharing tiles in workgroup memory, A loaded as vec4s): not faster
   than direct loads. It was removed.
   - Its first run (explore 6, not kept) gave wrong results, because the benchmark bound the untransposed A to it.
   - Explore 7 is the corrected run, `ok: true`.
   - Its offsets needed `@builtin(subgroup_id)`: offsets computed from the thread index were rejected ("requires
     argument 1 to be uniform").
